The detail is in its own deck: Path 3: The fleet is going to get big.

Path 3 is the ground the other two stand on: the fleet itself. Two ideas. Clusters become cattle: built from code, numbered, replaceable, nobody's pet. And developers never write a cluster name; an app declares constraints, like PCI and GPU, and the platform resolves them to clusters. Four stages. Stage 1 starts now and costs almost nothing: cluster labels become an API, which needs a schema and an owner. Path 1's fleet waves depend on it, which is the second rope. Then fleet delivery in waves, then lifecycle, which is EKS as our one orchestrator with Auto Mode and an upgrade window that's a policy rather than a project, and then Crossplane for the infrastructure app teams own, starting with S3. Two of these camps across the three paths get dates. The rest don't, on purpose.
