GOALS §5.5, §5.1 A. NVIDIA and Salesforce, N Clusters, One kubectl: “choose where the complexity lives”, and put it in the platform.

Now developers, and the question each one asks: where does my app run? Before, on the left: the payments repo has a file per cluster, an Argo CD Application for ny4, for ch4, a dozen for AWS, and values for each. The highlighted line: destination name ny4. Developers have to know our cluster names, and every new cluster means a PR in every app repo. After, on the right: one block in the app's repo. Tier prod, regions aws-1 and aws-2, a warm standby in the second cloud, six replicas. No cluster names. That's our small API; the platform turns it into an ApplicationSet cluster generator selecting on labels the clusters already carry. Click. The thirtieth cluster arrives from the Region claim already labelled. Payments lands on it, and nobody opens a PR in the payments repo. NVIDIA and Salesforce made the same point from the other side: choose where the complexity lives, and put it in the platform. And because it's labels, the app already runs in both regions.
