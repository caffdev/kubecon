GOALS §2.1–2.2: write policies against the action, not the actor. Google, Goodbye Webhooks, Hello CEL: native admission policy, GA since Kubernetes 1.30; Kyverno runs the same CEL in CI.

Identity says who the agent is. Policy says what anyone may do, and the trick is to write the rule against the action, not the actor. On the right, one CEL rule as a native ValidatingAdmissionPolicy, GA since Kubernetes 1.30, no webhook to keep alive. Every container image comes from our registry, pinned by digest. It never mentions people or agents. On the left, three actors send the same bad change: a person with kubectl, the pipeline from a merged PR, an agent through a tool call. The pipeline and the agent meet the rule in CI first, through kyverno test, so the PR fails before anyone reviews it. For an agent, a failed test is something it can read and fix. The person with kubectl skips CI; that's what admission is for. Click. All three meet the same rule there, with the same message. One rule set for people and agents. That's why agent governance mostly comes for free, if the rules are already there. Policy stops what shouldn't happen. Telemetry shows what did.
