Workloads first. Here's one agent as Kubernetes sees it: a Job. Jenkins, an alert or a schedule creates it, it does one task, and it's gone. Five fields matter. runtimeClassName gvisor: the code it runs talks to gVisor's kernel, not the node's. More on that next. serviceAccountName: in AWS, wired to Pod Identity, so it gets a short-lived role. No keys in the image. automountServiceAccountToken false: no Kubernetes API token just because it's a pod. activeDeadlineSeconds: killed at fifteen minutes, whatever it's doing; ttlSecondsAfterFinished cleans it up, and its logs are already in the lake. nodeSelector and tolerations: agents run on their own tainted pool, which Karpenter grows for a burst and empties after. Nobody approves each agent; the spec is the approval. Podium runs this shape: every coding agent an isolated pod. One catch we found writing this: Auto Mode can't run gVisor or Kata, so the agents pool is self-managed Karpenter on our own AMI. Verify before we build it. runtimeClassName is the line that matters, because a container is not a cage.
