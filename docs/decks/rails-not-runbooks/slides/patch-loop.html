Progressive Delivery for Trust: How Agents Earn the Right to Merge (Transfix, deck p9, p17). Fighting Fire with Fire (KubeEdge maintainers; no deck). The PR is our illustration.

Put that next to everything we built, and the circle closes. From the top. A new CVE lands, found by their agent or anyone's. The lake finds it: that query from earlier, which clusters run the image. Our agent drafts the fix. Click. The fix is a pull request with a one-line diff: payments moves to a new image digest, rebuilt with the patched OpenSSL. Then CI runs the same rules as anyone's change, and the team approves; the agent can't approve its own PR. Then the waves roll it out, each step gated on status, as NVIDIA showed. Click. Remember Transfix: models produce evidence, code decides authority. This agent has climbed to the permission rung, and it still only proposes; the agent that opens the PR is never the one that approves or merges it. Authority grows from a track record read by rules, not from trust. KubeEdge's maintainers already run the attacker-side version: agents reading disclosures and proposing patches. In the middle: days, from a CVE to every cluster. Same team, same pipeline; the agents make it go round faster. Before the ask, one more list: what we won't build.
