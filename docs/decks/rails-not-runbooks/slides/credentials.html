The scoped token is the whole credentials story. The agent never holds a password. Left to right. The agent carries a pass: a workload identity issued to that pod, read-only, short-lived and rotated. No key file, no token in an environment variable. At the gateway the pass becomes a token for one call. The real secret sits in the store behind the gateway and never crosses the dashed line, not into the agent's context, prompt or image. If an agent is tricked into printing everything it knows, there's nothing worth printing. Click. In AWS, this is the whole wiring: one Pod Identity association between the triage-agent service account and a read-only role. That's the serviceAccountName line from the Job. On-prem, the same idea is a SPIFFE ID from SPIRE. Secrets apps do need are synced by External Secrets, never written in YAML. The store itself is still GOALS section nine. Identity says who the agent is. Policy says what anyone may do.
