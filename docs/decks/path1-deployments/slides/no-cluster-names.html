ApplicationSet label selector

The label vocabulary is Path 3's first stage, and it is stage D's entry gate here.

A cluster name in an app repo is a bug. It hard-codes the one thing that live-live regions and rolling upgrades need to keep fluid. So the developer stops writing a cluster name, the crossed-out line, and declares constraints instead: regions, compliance, capability. The platform resolves those to clusters. And we already have the cheap first step. The ApplicationSet cluster generator matches clusters by label selector. It's in Argo CD today and costs nothing. Add rolling sync and that fan-out becomes waves: wave one, check health, wave two. OCM, Karmada and the cluster-inventory ClusterProfile work would all consume the same vocabulary if we ever needed them; we've seen ClusterProfile as a capability, not something we've run. So this is a vocabulary problem more than a tooling problem. The vocabulary is Path 3's first stage, and it's the entry gate for stage D on this path. Last mechanism: how a version moves between environments.
