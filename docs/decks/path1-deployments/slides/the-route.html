Here's the trade as a climb: five stages up one face, and watch where the click comes off. A, by January: auto-sync and self-heal in non-prod only, with the guardrails in the same pull request, never a follow-up ticket. Prune false on stateful and cluster-critical resources, PruneLast, a sync window on prod, and a reclaim-policy audit. Reloader goes in too, so a config change actually rolls its pods. A is done when non-prod has gone four weeks without a manual sync. B, in the first quarter: the one policy set in CI and at admission, and the freeze enforced by the cluster. It's done when a freeze blocks a sync with no human involved. And only then, the struck button: prod auto-sync goes on as the last item in B. Offer it earlier and we trade away the only reason teams agree. Above the button the route is dashed: that's what we trial rather than commit to. C, from the second quarter: promotion as a pull request, one app first. D, in the second half: the fleet rolls in waves with a health gate, once Path 3's cluster labels exist, and canary as a proof of concept. D is done when that gate has failed a bad wave at least once, because a gate nobody has watched fail is a gate nobody should trust. E, 2028, is a decision, not a commitment. Which brings us back to where we started.
