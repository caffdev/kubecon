Stage B is the trade from two slides ago, made real, and it's the least visible work on this whole path. One policy set, written once in Git, with its own tests, so the policies themselves are code we review. It runs in two places. First in CI: kyverno apply against the manifests and the cloud plans before anything merges. A violation becomes a ninety-second test failure, for a person or for an agent, and an agent can iterate against a test failure. It can't iterate against a rejected sync at two in the morning. Then at admission. The hot path is CEL ValidatingAdmissionPolicy, which runs in-process in the API server, so there's no webhook that can be down. Be honest about the flag: generating those CEL policies from our Kyverno set is a documented capability we haven't run yet. We verify it before anyone treats this box as a design. Kyverno keeps what CEL can't express: generation, mutation chains, and verifyImages, with our own images signed by cosign in CI. verifyImages starts in audit mode. The rule at the bottom is the one that matters for Path 2. Write policy against the action, not the actor. The policy that stops a person deploying a privileged container is the same one that bounds an agent, so most agent governance comes for free. Stage B gates stage C here, and it gates phase 2 of the agent path. Nobody demos it, which is why it's the stage that gets deprioritised. And the freeze becomes something the cluster enforces.
