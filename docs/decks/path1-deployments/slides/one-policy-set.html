The other two controls, policy and the freeze, turn out to be one machine. One policy set, written once in Git with its own tests, so the policies are code we review. It runs in two places. First in CI: kyverno apply against the manifests before anything merges. A violation becomes a ninety-second test failure, for a person or for an agent. Nobody can iterate against a rejected sync at two in the morning. Then at admission. The hot path is CEL admission policy, inside the API server, so there's no webhook that can be down. Be honest about the flag: generating that CEL from our Kyverno set is a documented capability we haven't run, and we verify it before anyone treats that box as a design. Kyverno keeps what CEL can't express. Now the freeze. Today it means someone refusing to click. Instead, the change record is approved in the ITSM system exactly as today, and projected into the cluster as a custom resource that policy reads. Admission never calls the ITSM API at request time, because a policy that calls an outside service fails closed the first time that service is slow. Argo CD's sync windows already cover the calendar freeze. And the line at the bottom is the one Path 2 depends on. Write policy against the action, not the actor, and the rule that stops a person also bounds an agent. Last mechanism: how a version moves between environments.
