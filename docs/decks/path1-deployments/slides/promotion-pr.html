Last mechanism: how a version moves from dev to stage to prod. Promotion is becoming a pull request. On the left, GitOps Promoter, which is our call. Each environment is a branch. A promotion is a commit and a pull request, with a commit status per environment. There's no state outside Git, so the PR is the audit record: the one artifact a human reviewer, an agent and an auditor all read. It composes with Argo's source hydrator, so Git holds what actually runs, with diffs a person can read. On the right, Kargo: Warehouses, Freight and Stages, with its own control plane and UI. It fits complex pipelines and release managers who live in a UI, and Meta runs about a hundred clusters with it. It would be a second control plane for us. What would flip it, stated so the decision looks as reversible as it is: per-environment commit status needs hand-wiring for auto-rollback; Promoter doesn't order across apps; and it's younger. Nearly every published comparison is written by someone with a stake, Akuity maintains both Argo CD and Kargo, so the answer is a two-week spike on one real app, not more reading. And the Kargo adoption figure in our notes came from a vendor post; we don't quote it. So why haven't teams asked for any of this?
