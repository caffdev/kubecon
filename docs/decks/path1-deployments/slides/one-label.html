This is the only canary pattern that works for things with no user traffic to split: admission webhooks, controllers, credential services. Which is most of what a platform team owns. Five moves. Isolate: run a canary instance beside production with its own deployment, service, config, and its own database schema and user. Route: only one dedicated canary-test namespace can reach it, using a namespace selector. No proxy, no mesh; the API server does the routing. Validate: run twenty-plus real workflows on real nodes against real data. Gate: an Argo CD PostSync hook job; exit zero advances, exit one fails the sync. Promote: cluster by cluster, automatically on pass. On the right is why you build the gate rather than a dashboard. A loud webhook outage got caught in about thirty minutes. A silent webhook change that quietly stripped GPUs from job specs lasted about two days. That's the bars, to scale. No human watching a graph catches the quiet ones. That pattern selects on labels. So should everything else.
