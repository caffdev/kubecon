Camp one is close, so let's define what reaching it means, because if the output is a summary nobody acts on, we've built a chatbot. This is an illustrative triage, not a real one. An alert fires. The agent posts four things, and these are the acceptance criteria. A relevance call: real, noise, or a duplicate of an open incident. A severity, stated in terms a responder can disagree with. Links out: the runbook, the dashboard, the deploy that correlates, the last three times this fired. And a suggested action. Then the responder accepts it, modifies it, or rejects it, and we log which. That log, on the right, is the product. It's the track record the camp-two gate reads before any agent gets to open a pull request. If we don't instrument it from day one, we arrive at that gate with no evidence. We don't start from scratch, either. HolmesGPT is an open-source investigation agent built for exactly this, alert-driven and read-only, and k8sgpt is a lighter rule-based option. We still need to confirm HolmesGPT's current Claude support before we commit to it. And none of this needs a cluster to start. It starts on laptops, this month.
