None of what we've described works unless we can see what each run did and what it cost. This is one alert-triage run, laid out as a trace. It's illustrative, not measured. An alert fires. Jenkins starts the job. Claude runs. It calls the model, asks Grafana for a dashboard through an MCP tool, calls the model again, searches the logs, calls the model once more, and posts its note to Slack. Every one of those is a span on the OpenTelemetry pipeline we already run, and every span carries the same labels: which team, which use case, which Jenkins run. The model calls carry their token cost. Add them up and you get a cost per task. That's the unit Verkada reports, thirty-three cents an alert, and it's the unit we'll report too. We use the OpenTelemetry generative-AI conventions rather than inventing our own attributes, because that standard is being written right now and we don't want to redo this next year. And here's the trick: turning telemetry on is also how we answer "what are we using AI for?" The inventory falls out of the instrumentation. With that in place, we can climb.
