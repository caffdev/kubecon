Here's the turn. Don't build an agent platform. Run Claude headless, in throwaway pods, through the CI we already trust. This is the whole runtime, and right now it's all grey, because it's all something we already run. Something happens: a pull request opens, an alert fires, someone types a Slack command, the nightly cron runs. Jenkins picks it up, the way it already does, with credentials, an audit log, retries and access control. It starts a throwaway pod in a namespace of its own. The dashed line is that namespace's network policy: the pod can only reach the gateways and the telemetry collector. Every model call goes to Claude, through the API or Bedrock. Every tool call goes to GitHub, Jira, Grafana, or a read-only view of Kubernetes. Click. Four pieces light up, and those four are the whole build. A Jenkins library step, claudeAgent, so a team writes one line instead of a pipeline. A hardened agent image: Claude Code headless, with managed settings baked in and telemetry on. The gateways, where quota, auth and audit live once. And a marketplace repo of skills, MCP configs and settings, which every laptop reads too. And to be clear about scope: we run Claude. We're not hosting a model, so GPUs and serving stacks stay off the table. Security's first question is going to be how far that pod can reach.
