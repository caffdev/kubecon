So we stay on EKS, and here's the first design rule for a big fleet: clusters are cattle, not pets. On the left, a pet. It has a name people know by heart. It was built by hand, it's been patched by hand, and nobody is quite sure they could recreate it from scratch. So nobody wants to upgrade it. On the right, cattle. Identical, numbered, created from code, replaceable. If one is sick, you rebuild it. Three rules make that real. Every cluster is created and upgraded from code, using Auto Mode with CDK or Crossplane: no cluster that nobody can recreate. New clusters default to EKS Auto Mode, which pushes node patching and upgrades to AWS; the management fee costs less than the engineer-hours we spend on node groups, and we keep self-managed Karpenter only where Auto Mode doesn't fit, like exotic GPU shapes. And we push platform add-ons off our nodes where we can: trial EKS Capabilities, managed Argo CD, ACK and kro, against self-hosting. Fewer controllers on our nodes means fewer things to upgrade. Cattle still need upgrading, and that has to stop being a project.
