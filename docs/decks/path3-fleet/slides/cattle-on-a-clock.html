EKS-VS-ECS.md §4. ⚠️ Fees from third-party write-ups; check AWS pricing before quoting.

The first design rule for a big fleet: clusters are cattle, not pets. This is a cluster's clock. Every EKS minor version gets fourteen months of standard support. Inside that window the control plane costs about ten cents an hour per cluster, around seventy-three dollars a month. On the cheap side, the herd. Identical, numbered, built from code with CDK or Crossplane, so any one of them can be rebuilt. New clusters default to EKS Auto Mode, which pushes node patching and upgrades to AWS; we keep self-managed Karpenter only where Auto Mode doesn't fit, like exotic GPU shapes. And every cluster is upgraded before month fourteen, by a named owner, because the policy says so, not because someone remembered. Click. On the other side, the pet. It has a name everybody knows. It was built by hand and patched by hand, and nobody is sure they could recreate it, so nobody wants to upgrade it. It drifts past month fourteen into extended support, about sixty cents an hour, around four hundred and forty dollars a month, per cluster: six times as much. Those fees come from third-party write-ups, so we check the pricing page before anyone quotes them. But the shape is the point: a missed upgrade is now a line on the bill, not just a risk. Skip-level upgrades, what LinkedIn did, make the window easier to hit. And we should measure our own toil, hours per EKS minor last year, so this argument carries our number, not just theirs. Cattle get upgraded in bulk, so every change needs its own proof.
