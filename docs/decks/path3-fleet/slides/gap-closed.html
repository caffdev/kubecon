EKS-VS-ECS.md §3. ⚠️ Fee levels come from third-party write-ups; check AWS pricing before quoting a number.

The old argument for ECS was that it's simpler. That was true in 2022. It isn't now. EKS Auto Mode went GA in December 2024; ECS Managed Instances in the autumn of 2025. Side by side, they're the same product shape. AWS runs and patches the nodes on both. Both charge EC2 plus a per-instance management fee; we need to check the actual fee levels on the pricing pages before anyone quotes a number. And when AWS cut GPU fees in July this year, they cut them on both, on the same day. So what's left is the API. EKS has managed Argo CD, ACK and kro running in the AWS control plane; ECS has nothing comparable. Nearly everything we'd run alongside our apps ships as a Helm chart first; on ECS each one becomes a task definition we write and maintain. And Kubernetes runs on-prem and in every other cloud; ECS runs on AWS. For us, the Kubernetes API is the asset, not the cost. So we stay on EKS. Here's how to run a big one.
