GOALS §8; Velero project update (Red Hat); Kubernetes Data Protection WG.

The floor is the one area where being wrong is unrecoverable. Backups are a rumor until we restore one. Pause. Three steps, in order. Retain: audit every storage class, because Delete is the default reclaim policy, and it's the wrong one for data we care about. Back up: Velero on a schedule, with consistent, incremental snapshots, and nothing bespoke, because there's now a Kubernetes data protection working group standardising exactly this. And the one that's lit: drill. Restore into a scratch cluster on a calendar, and time it. The drill matters more than the backup. A cluster we can rebuild and restore is a cluster we're willing to upgrade aggressively, and that's the whole deck. One cheap extra while we're down here: alert on etcd database size at fifty and seventy-five percent. AWS showed how pod status churn alone can push a cluster read-only with zero crashed nodes. That alert catches it in days, not minutes. So, five decisions.
