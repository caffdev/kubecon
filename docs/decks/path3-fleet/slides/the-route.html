The seamCDK below, Crossplane above. Decision 3.

Four stages, and the first one is nearly free. Stage 1, starting now: cluster labels become an API. A schema, an owner, and a policy that won't let a cluster join the fleet without its labels. It costs agreement, not a tool. And three things wait on it. Path 1's fleet waves select on cluster labels. Cluster thirty-one only joins itself if its labels exist. And developers only stop naming clusters when there's a vocabulary to use instead. Stage 2: fleet delivery in waves, ApplicationSets with rolling sync, which we share with Path 1. Stage 3: lifecycle. Auto Mode as the default for new clusters, the support window as a policy, and Hybrid Nodes piloted at one on-prem site, so on-prem and EKS become one control-plane model. Then the dashed line. Before anyone builds stage 4, we mark the seam. Below it, the landing zone and CDK: accounts, guardrails, VPCs, the EKS clusters themselves, things that change rarely. Above it, Crossplane and kro, starting with S3 and moving to the infrastructure app teams own, things that change constantly. Two tools fighting over one resource starts with an unmarked line. That's decision 3, and it needs a diagram with the line drawn, not a debate. And above the seam we have no paved road yet. Our lean: build the road first, templates in Git and the label vocabulary, and buy a portal later, as a window onto it. Before we climb, the floor under all of it.
