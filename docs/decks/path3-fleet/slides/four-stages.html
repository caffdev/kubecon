That's the summit. Here's the route: four stages, and the first one is nearly free. Stage 1, starting now: cluster labels become an API. That's a schema, an owner, and a policy that won't let a cluster join the fleet without its labels. It costs a few days of agreement, not a tool. Stage 2: fleet delivery in waves, ApplicationSets with rolling sync, which we share with Path 1's stage D. Stage 3: lifecycle. Auto Mode as the default for new clusters, the support window as a policy, and Hybrid Nodes piloted at one on-prem site so on-prem and EKS become one control-plane model. Stage 4: Crossplane for the infrastructure app teams own, starting with S3. Why stage 1 first? Three things wait on it. Path 1's fleet waves select on cluster labels. The thirty-first cluster only joins itself if its labels exist. And developers only stop naming clusters when there's a vocabulary to use instead. Stage 4 needs one line drawn before anyone builds on it.
