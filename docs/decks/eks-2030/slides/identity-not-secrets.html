“Kubernetes Secrets Were a Bad Idea. Now What?” RBC, session title

Move three: identity, not secrets. Top left is how most platforms start: a password in an environment variable. Long-lived, copied into places, never rotated. We void that from the first cluster. Instead, every pod gets one identity. Istio already gives each pod a SPIFFE ID, built from its namespace and service account, and a short-lived certificate for mutual TLS. Vault trusts the same identity through its Kubernetes auth and hands out database credentials that expire. And AWS access goes through EKS Pod Identity, so there are no static AWS keys anywhere. Click. Coinbase did this the hard way, as a retrofit. They replaced a homegrown auth system with SPIFFE across more than four thousand services in seventy-nine clusters. CPU dropped seventy percent. Each hop got four to ten milliseconds faster, about fifty milliseconds off a typical service chain. And they got to a hundred percent adoption. RBC's talk title says the rest: Kubernetes Secrets were a bad idea. Istio gives us that identity. At scale it will also give us two million metric series, if we let it.
