Sheet five: agents. An agent isn't a tool on someone's laptop. It's a workload, and a strange one: it runs for minutes, costs tokens, gives a different answer each time, and runs code nobody reviewed. So here's one agent session, exploded. In the middle, the Claude Agent SDK harness, in our own image, one pod per session. Events come in at the top: an alert, a webhook, a schedule. And there's exactly one way out, at the bottom: it writes merge requests. Nothing else. Click. One: its own kernel, a microVM or gVisor, picked with one field on the pod spec; AWS demoed microVM pods on EKS. Click. Two: its own identity, a service account per agent, so Istio can say which agent may call which tool; Bancolombia showed that. Click. Three: keys it never sees; Vault puts them on its outbound calls. Click. Four: an exit list through Istio. Click. Five: caps on CPU, tokens and time, and an off switch: delete the pod. Those five are from Infisical's demo, and every one is Vault, Istio or plain Kubernetes. As IBM put it: you probably don't need an agent platform; you already run the parts. So what do the agents do first? The thing that's eating us: toil.
