Here's 2030 as a spec sheet, not a headcount. It's stamped preliminary because these are targets for us to agree. Each row is one sheet of the set: one move. Sheet one: a new cluster comes from a pull request, the same day. LinkedIn already takes a Kubernetes minor across two hundred and fifty clusters in seven business days. Sheet two: a new service is about ten lines. Sheet three: zero long-lived secrets in pods. Sheet four: every metric series and every dollar has an owner. Sheet five: an agent takes the first look at every alert, and opens the routine change. A person approves it. That line is red because a person stays in it, in 2030 too. The footprint row is in a cloud because it's open: two AWS regions, yes, but do we exit on-prem fully, or keep it as one more cluster run like the others? Along the bottom, what's not in the set. By a rough count of titles, about a third of the AI talks were about running models. We call Claude, so we skip all of it. No Kargo, no Promoter, no progressive sync, no second orchestrator. Five sheets get us there. Sheet one is the clusters, and it starts with the worst day anyone described at the show.
