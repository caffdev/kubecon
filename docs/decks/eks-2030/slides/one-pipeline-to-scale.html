Yahoo, “Two-Stage OTel Aggregation”, posted slides. Band height to scale.

Sheet four: one telemetry pipeline. We keep Prometheus, Grafana and Splunk. We add one OpenTelemetry tier in front: an agent on every node, a gateway per cluster. This drawing is to scale. The band's height is Yahoo's Istio metric series on one production cluster: twenty-four thousand pods, two point oh six million active series. They collapsed it in two stages inside the cluster, per node and then across the cluster, and only the merged series leave. Two hundred and eighty thousand. Same traffic. Click. Eighty-six percent fewer series, about a hundred and forty thousand dollars a year back, on one cluster. And once every signal goes through the gateway, a backend is just exporter config. Nobody redeploys a service to change where data goes. Click. And the catch, because they said it out loud: sent to a second backend, the data read almost three times low, because several gateway pods wrote the same series in the same second. It isn't fixed yet. We'd test for that before we trust a dashboard. The same gateway is where every dollar gets an owner, with a team label on every pod, enforced at admission. With that in place, we can afford the next workload: the agents.
