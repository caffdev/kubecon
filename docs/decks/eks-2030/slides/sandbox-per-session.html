An agent writes and runs code nobody reviewed. So each session gets a stronger box than a normal pod. This is an exploded drawing of one agent session: the pod in the middle, five parts pulled out. Click. One: its own kernel. A sandboxed runtime, a microVM or gVisor, chosen with one field on the pod spec. AWS demoed hardware-isolated microVM pods on EKS doing exactly this. Click. Two: its own identity. A service account per agent, which Istio turns into a SPIFFE identity. Bancolombia showed Istio policy deciding, per request, which agent may call which tool on behalf of which user. Click. Three: keys it never sees. Vault brokers credentials onto its outbound calls; nothing sits in its environment. Click. Four: an exit list. Egress goes through an allowlist, and the cloud metadata endpoint is blocked. Click. Five: limits and an off switch. Per-session CPU, tokens and time, and when the pod is deleted, its access ends. Those five come from Infisical's demo, and they map one-to-one onto Vault and Istio, which we already chose. Click. One honest disagreement from the show. Mastercard says no MCP and no shell, just functions. Verkada says MCP is boring plumbing. Both agree that the boundary matters more than the protocol, and the boundary is what we're building.
