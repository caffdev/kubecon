Move five: agents. The first thing to get right is what an agent is. It isn't a tool on someone's laptop. It's a workload, and a strange one. GenbaNEXT put it in a table. A normal request takes milliseconds, costs nearly nothing, and gives the same answer twice. An agent task takes minutes, costs tokens, gives a different answer each time, carries state between steps, and when it fails, it fails after you've already paid for half of it. Click. So here's our build, as a section through one agent pod. Inside: the Claude Agent SDK harness, in our own image. It's started by events: an alert, a webhook, a schedule. Its state lives outside the pod, in Postgres, the way Mastercard does it, so a restart resumes instead of starting over. And it writes in exactly one way: a merge request. Click. IBM's line was the one I wrote down: you probably don't need an agent platform, you already run the parts. Uber ran over eight hundred thousand agent runs in one month on the same workflow engine it uses for everything else. A workload that writes and runs its own code needs a stronger box than a normal pod.
