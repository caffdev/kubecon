Nutanix, “GitOps Meltdown”, posted slides. They ran Flux; same shape in Argo CD.

Sheet one: clusters are cattle. We build every cluster from Git and rebuild it from Git. Which tool writes the bottom layer, Terraform, Cluster API or ACK with kro, is still open. The rule isn't. But that cuts both ways. Nutanix ran thirty-nine production clusters from one management cluster. An admin deleted the top-level object of the tree, and pruning did exactly what it was built to do. Twelve minutes in, the delete stalled, because the controller had deleted itself. Eight hours later they restored it, it read the same desired state, and finished the job: all thirty-nine gone. Four days to get clusters and apps back, and the backups had never been restore-tested. They ran Flux; Argo CD's app-of-apps has the same shape. Four guards, all basic. Click. No single root owns the fleet: one Application per cluster. Click. Make bulk delete hard: Prune=false on clusters and stateful infrastructure, and a CEL policy that refuses deletes. The catch: we check those names on our Argo CD version first. Click. Data outlives objects: Retain on storage, and Git outside the clusters. Click. Restore on a schedule: an hour of data loss, thirty minutes to restore, proven on a game day. The good news: they redeployed all thirty-nine from Git by day two. That's the fleet.
