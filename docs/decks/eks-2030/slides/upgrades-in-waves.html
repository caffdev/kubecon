Creating clusters is the easy half. Keeping them current is where the hours go. This is NVIDIA's slide. They had two kernel CVEs land days apart. They wrote the fix and, in the same package, the check that fails if the fix didn't take. Then an agent applied it cluster by cluster. It polled the status field, the same one kubectl shows, moved on when it said complete, and stopped and called a person when it said erroring or blocked. About fifty-six hundred nodes converged in thirty minutes, across sixteen clusters, unattended. And the agent did stop once: some clusters had tainted control-plane nodes, so it escalated, they fixed the config, and re-applied. Click. Our version is simple. Every change goes dev, then one production canary cluster, then the rest. Between each wave is a check that has to pass. On EKS, AWS upgrades the control plane for us. We own the add-ons, the nodes, which we replace rather than patch, and the checks. Waves make a good change fast. They make a bad change fast too.
