kubeadm upgrades one node and one minor at a time, three times a year.

# for every node, one after another kubectl drain node-4 --ignore-daemonsets apt-get install -y kubeadm='1.37.*' kubeadm upgrade node apt-get install -y kubelet='1.37.*' kubectl='1.37.*' systemctl restart kubelet kubectl uncordon node-4

kubeadm can’t skip a minor, so each row below has to finish before the next one starts.

Here's what one upgrade actually is, on a kubeadm cluster. In the box: the runbook for a single node. Drain it. Upgrade kubeadm. Run the upgrade. Upgrade kubelet and kubectl. Restart kubelet. Uncordon it. Then the next node. The control plane nodes go first, one at a time, then the workers, one at a time. Below: that's one row. Nine nodes, six steps each, fifty-four steps for one cluster, and a person waiting on every one of them. Call it a day. And kubeadm won't skip a minor version. Kubernetes ships three a year, roughly April, August and December, so that row happens three times a year. Per cluster. On-prem we'd have six of them by the end of the story. That's the clusters. And they're the small part.
