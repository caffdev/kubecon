The tools get the treatment we already give apps. Read it from the left. The test cluster, then one canary with real workloads, then the prod fleet in waves: wave one, wave two, the rest of prod. A new version of a tool moves outward one ring at a time. One ApplicationSet per tool, with progressive sync taking it a wave at a time; a cluster joins a wave with a label, so cluster twenty-nine just gets a label and it's in. Between every ring there's a gate. Click. A new Prometheus goes onto the test cluster. Its gate passes: targets up, rules evaluating. So it moves out. Click. It reaches the canary, and this time the gate fails. Targets dropped after the upgrade. Click. And here's the point. Nobody decides anything. The pipeline rolls the canary back on its own. Wave one never started. Prod never saw it. The person in orange finds out from a message in the morning, not a phone call at night. On the right, each tool brings its own gate. Different checks, same machinery. This isn't our invention. LinkedIn showed it for their cluster services: the gate is an Argo CD PostSync job. Exit zero, the wave advances; exit one, the sync fails and it rolls back. A release went from about a week of manual testing to about an hour. The failure on screen is our example, not their incident. And the pipeline also needs to know when not to run at all.
