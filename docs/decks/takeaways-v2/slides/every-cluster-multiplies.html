Here's what one cluster costs him in a year. The top lane is Kubernetes itself. Three minor versions a year, roughly April, August and December. On a kubeadm cluster each upgrade is that block: nine nodes, six steps a node. Drain it, upgrade kubeadm, run the upgrade, upgrade kubelet and kubectl, restart kubelet, uncordon. Then the next node. Fifty-four steps, every one waiting on the last. Call it a day. And kubeadm can't skip a minor, so all three happen, every year. Below it, the platform on that cluster. Argo CD to deploy, Prometheus to measure, the Splunk OTel collector to ship telemetry, Karpenter to scale nodes on the cloud clusters. Each has its own release train, and they don't line up with each other or with Kubernetes. The timing here is illustrative, but the shape isn't: lots of small rollouts, all year, scattered. That's one cluster. Now multiply by twenty-eight. Every new cluster brings all five trains with it, and on a hand-run fleet each stop is somebody's afternoon. What hand rollouts leave behind is version skew: if you asked which version of Prometheus each cluster runs, someone would have to go and look. So add it all up, and put it against one person's year.
