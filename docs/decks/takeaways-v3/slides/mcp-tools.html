Caged, an agent still has to do things, and it does them through tools. MCP is how: the agent asks a tool server to open a pull request, request a bucket, read the cluster or file a change record. Notice what the agents build infrastructure with. Not a kubeconfig with admin rights. A pull request, and a Crossplane claim inside that pull request. So everything an agent builds still goes through review, the pipeline, the gates and the windows we just saw. The important box is the one in the middle: one gateway every tool call goes through. It's where we check who may call what, with permissions that come from the corporate directory rather than whatever token someone started a server with, and where every call gets logged. Three ways to get it. Obot is open-core and does directory-managed permissions. ToolHive, from Stacklok, is open source and pairs with the Cedar policy work AWS and Stacklok presented. Or we build our own thin proxy, and then every feature after the first is ours to build and keep. The order matters: choose on enforcement first, then pick the tools. A bake-off, not a default. And the gateway is also where the passwords live, so the agent never holds one.
