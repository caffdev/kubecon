A lake is a snapshot. Fine for triage and trends. A gate mid-rollout still reads live metrics through one narrow, audited tool.

Everything that layer collects has to land somewhere the agents can read, and where it lands matters more than which tool it is. Three streams come down, one from each path. From the fleet: cluster state, snapshotted into a database, plus metrics. From delivery: every sync, every rollout, every gate result. From the agents themselves: their traces and tool calls. They all run into one lake. The agents sit on the shore and read. That's how they decide things: is this alert real, did this canary actually get worse, which hour is quiet enough to upgrade this cluster. And here's the rule. There's no path from the shore back up to production. Read-only extraction is what lets us say yes to agents analysing prod without saying yes to agents holding prod credentials. That's a security control, not just plumbing. Let me be honest about the limit. Mastercard argued the other side at the show: a lake is a snapshot, and a stale index can mislead a model. They let theirs call live APIs through a narrow, audited tool instead. They're right for live decisions. So: the lake for triage and trends; a gate in the middle of a rollout reads live metrics through one narrow tool. NVIDIA and Workday added the other lesson: raw telemetry confuses models, so put a typed query layer over the lake. And one of the first things worth deciding from it is how big every pod should be.
