The gateway is also where the passwords live, and that's deliberate. The agent never holds one. Follow it left to right. The agent carries a pass: a workload identity, issued to that pod, valid for fifteen minutes, saying what it is and that it's read-only. No key file, no token pasted into an environment variable. At the gateway, that pass is exchanged for a token scoped to exactly one call: this tool, this action. The real secret, the database password or the cloud key, lives in the store behind the gateway. It never crosses the dashed line into the agent: not into its context window, not into its prompt, not into its image. So if an agent is tricked into printing everything it knows, there's nothing worth printing. Four patterns underneath. Workload identity, from EKS Pod Identity or SPIFFE. Token exchange at the gateway. Short-lived, dynamic credentials, so anything that leaks expires on its own. And secrets synced from the store by External Secrets, never written into YAML. We still have to pick the store; that's GOALS section nine. These patterns make the choice matter less. Identity says who the agent is. Policy says what anyone may do.
