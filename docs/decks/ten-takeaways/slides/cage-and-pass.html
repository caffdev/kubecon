DECIDE

Rules six and seven also share a slide, because they're the two walls around one agent: where it runs, and who it is. Every agent gets its own kernel and a pass that expires. Where it runs first. Agents run code they wrote a minute ago, and every container on a node shares one kernel. So a container is not a cage. It's drawn as a lab's containment levels. Level one, a plain container: fine for our services, not for agent-written code. Level two, gVisor, a user-space kernel in between. Level three, Kata microVMs: the agent gets its own kernel, and Microsoft's pod snapshots make the start-up cost bearable. That's the row in black, the one we'd trial first. Level four, an agent substrate that bundles identity, sandbox, session and egress into one layer, which Solo.io keynoted with Anthropic and Google; for us it's still a decision, or at least a vocabulary to pick. Now who it is: the pass clipped to the door. A house key works forever, for whoever holds it. That's a long-lived secret, and a secret an agent can read is a secret that can leave the building. A pass names who you are, is good for one trip, and is worthless an hour later. This one is illustrative: a SPIFFE identity for a triage agent, valid for fifteen minutes, checked by Cedar or OpenFGA, and no static secret on file. Coinbase, Google and Microsoft, RBC and Veritas Automata all argued some version of it. So: a cage, and a pass. Never the house keys. How far up the mountain do we let agents go, and when?
