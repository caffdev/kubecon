Rule three: backups are a rumor until you restore. This is the one item on our whole list where being wrong is unrecoverable, so it gets a safety sign. Here's why it's a rumor. Nutanix gave the scariest talk of the week: one commit cascaded into deleting thirty-nine production clusters. When they reached for the backups, the latest Velero snapshot was twelve hours old, partial, and the recovery pipeline had never been tested end to end. Their own line was that a backup strategy is a hypothesis until you've restored from it. So three steps, posted like an emergency procedure. Retain: audit every storage class, because Delete is the default reclaim policy and it's the wrong one for data we care about. Back up: Velero on a schedule, and nothing bespoke, because Broadcom's new data protection working group is still standardising the primitives. Drill: restore into a scratch cluster on a calendar, and time it. The drill is the point. A cluster we can rebuild is a cluster we're willing to upgrade aggressively, which takes us back to rule one. That's the ground. Now the path every change takes across it.
