WHO WE SAW RUNNING IT: Red Hat, the "Sandbox Your Agents" keynote; Microsoft, Kata pod snapshots; Google, agent sandboxes on secure runtimes; Solo.io with Anthropic and Google, the Agent Substrate keynote; NTT, Lima as a local sandbox; vCluster, sandboxed MCP servers.

Rule seven: a container is not a cage. Agents run code they wrote a minute ago, and every container on a node shares one kernel. So the rule is that each agent gets a microVM-grade boundary, and its own identity, before it ever gets a credential. It's drawn like a lab's containment levels. Level one, a plain container: fine for our own services, not for agent-written code. Level two, gVisor, a user-space kernel in between. Level three, Kata microVMs: the agent gets its own kernel, and pod snapshots make the start-up cost bearable; that's the one we'd lead with. Level four, an agent substrate that bundles identity, sandbox, session and egress into one layer; that one's still a decision, or at least a vocabulary to pick. Red Hat, Microsoft, Google, Solo.io with Anthropic, NTT and vCluster all presented on it. So how far up the mountain do we let agents go, and when?
