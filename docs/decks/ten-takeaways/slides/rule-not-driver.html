TITLE II: POLICY AS CODE

KUBERNETES CODE, ANNOTATED: SALT LAKE CITY EDITION

§ 2.1

The rule doesn't ask who's driving.

Write policy against the action, not the actor. The rule that stops an engineer shipping a privileged pod also bounds an agent, and it runs in CI before either one meets admission.

§

No workload shall run privileged, mount the host, or reach an unapproved model or tool, whoever authored the change.

(a)

Enforced at admission in CEL, with no webhook in the request path.

(b)

Run first in CI, so a violation is a failing test an agent can fix.

(c)

No sync in a change window without an approved change record.

— 2 — ADOPT: GOALS §2.1 TO §2.4

Rule five: the rule doesn't ask who's driving. This is set as a statute on purpose. The clause never names a person or an agent: "No workload shall run privileged, mount the host, or reach an unapproved model or tool, whoever authored the change." That's the whole idea. Write policy against the action, not the actor, and the rule that stops an engineer shipping a privileged pod also bounds an agent. The sub-clauses are the mechanics. Enforced at admission in CEL, with no webhook in the request path. Run first in CI, so a violation is a failing test an agent can fix. And clause (c) is our own proposal: no sync during a change window without an approved change record. In the margin, the cases we heard: AT&T, Google, JPMorganChase, Grainger, and Nirmata with Nutanix on policy at the AI gateway. Which matters most for the drivers that aren't people.
