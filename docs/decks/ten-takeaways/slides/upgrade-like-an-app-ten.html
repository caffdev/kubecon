Rule one, and it's about the thing that gets big whatever we do: upgrade the fleet like you ship an app. Every fleet talk at the show was really an upgrade story. Here's the cleanest one. LinkedIn took production from Kubernetes 1.31 to 1.34. One minor version at a time, that's six fleet waves and forty business days: every bar on this strip. With skip-level upgrades, one rollout and a promotion, it took seven. The red ones. The others along the bottom are the same pattern. NVIDIA converged about fifty-six hundred nodes in thirty minutes for two kernel CVEs, because the change shipped with its own check. Meta runs about a hundred clusters with about fifteen engineers. Salesforce runs a thousand. The common thread: ship each change with the check that fails without it, roll it out in waves, and nobody upgrades a cluster by hand. A fleet that big is built from code. So where does one tool's code stop and the next one's start?
