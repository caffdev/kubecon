BACKUPS ARE A RUMOR UNTIL YOU RESTORE.

The one item on our list where being wrong is unrecoverable. Retain by default, back up with Velero, and drill the restore until we trust it enough to upgrade aggressively.

1

RETAIN

Audit every StorageClass. Delete is the default reclaim policy, and the wrong one for stateful production data.

2

BACK UP

Velero on a schedule, with consistent, incremental snapshots. Nothing bespoke while the primitives are being standardised.

3

DRILL

Restore into a scratch cluster on a calendar, and time it. A cluster we can rebuild is one we'll upgrade.

SEEN AT THE SHOW: Red Hat's Velero project update, "Faster Backups, Consistent Snapshots, Incremental Everything"; Broadcom on the new Kubernetes Data Protection working group. GOALS §8.

Rule three: backups are a rumor until you restore. This is the one item on our whole list where being wrong is unrecoverable, so it gets a safety sign. Three steps, posted like an emergency procedure. Retain: audit every storage class, because Delete is the default reclaim policy and it's the wrong one for data we care about. Back up: Velero on a schedule, and nothing bespoke, because there's now a working group standardising the primitives. Drill: restore into a scratch cluster on a calendar, and time it. The drill is the point. A cluster we can rebuild is a cluster we're willing to upgrade aggressively, which takes us back to rule one. That's the ground. Now the path every change takes across it.
