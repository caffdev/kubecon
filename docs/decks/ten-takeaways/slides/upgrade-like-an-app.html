Rule one, and it's about the thing that's going to get big whatever we do: upgrade the fleet like you ship an app. Every fleet talk at the show was really an upgrade story. LinkedIn took production across three Kubernetes minor versions in seven business days, in one skip-level rollout; it used to take forty. NVIDIA converged about fifty-six hundred nodes in thirty minutes for two kernel CVEs, because the change shipped with its own check. Meta runs about a hundred clusters with fifteen engineers. Salesforce runs a thousand. The common thread: ship each change with the check that fails without it, roll it out in waves, and nobody upgrades a cluster by hand. A fleet that big is built from code. So where does one tool's code stop and the next one's start?
